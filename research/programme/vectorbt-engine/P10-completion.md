# P10 completion note: the uncontroversial part of the final audit's punch list

**Date:** 2026-11-06. **Branch:** `vbt12/engine` (nothing committed, staged, tagged or pushed). Terms: **WFO** = walk-forward optimisation. **PIT** = point-in-time (which S&P 500 stocks were members on a given day). **DSR** = deflated Sharpe ratio. **Tape** = the frozen daily-bars file `data/snapshots/ohlcv_20261106.parquet`. **Golden** = a frozen result a test or script compares with.

## 4. The DSR numbers (item 6)

* **Multi-combination grids (every P5 evidence run: grids of 3 to 216 combinations):** the multi-trial path was already `engine.stats.dsr`; the code is unchanged. Core17 and dsr0 reproduce exactly (section 3).
* **One-combination grids (the only case that moves):** the old path called the hand-written `dsr_check` with the scorer's Sharpe and pandas skew and kurtosis; the new path asks vectorbt for the probabilistic Sharpe ratio against zero from the returns. Measured on the 17-fold SP500 ensemble run with the one-combination live grid (`Ensemble.live_grid()`), tape of 2026-11-06, old logic restored in the driver and run next to the new one: **17 folds, maximum absolute DSR difference 1.1e-16, 0 gate flips.** Raw artifact: [p10-evidence/dsr_one_combo.py](p10-evidence/dsr_one_combo.py) and [p10-evidence/dsr_one_combo_result.json](p10-evidence/dsr_one_combo_result.json) (per-fold DSR values and gate results of both logics). The only case that can move is a window whose Sharpe is undefined (no trade): the old path returned `NaN` for a one-trial grid and the gate failed; the new path reports `0.0` and the gate fails, as it already did for multi-trial grids.
* No headline run used a one-combination grid (the audit made the same observation), so no cited number moves.
