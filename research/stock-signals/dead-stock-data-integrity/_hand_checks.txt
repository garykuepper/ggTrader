## 3. The slow `daily_of()` probe (the "over 12 minutes" figure)

**3a. Query as first run (with the stock-spans filter), rerun with a 60-second limit**

```sql
SELECT DISTINCT d.permno FROM kaggle_crsp.daily_of(1::bigint) d
WHERE d.shrcd = ANY(ARRAY[10,11]) AND d.exchcd = ANY(ARRAY[1,3])
AND d.date >= '2004-01-01' AND d.date <= '2024-12-31'
AND d.permno IN (SELECT permno FROM market.stock_spans WHERE release_id = 1 AND permno IS NOT NULL);
```

Result: stopped by the 60 s limit after 60.1 s: QueryCanceled.

**3b. Same query without the stock-spans filter**

```sql
SELECT DISTINCT d.permno FROM kaggle_crsp.daily_of(1::bigint) d
WHERE d.shrcd = ANY(ARRAY[10,11]) AND d.exchcd = ANY(ARRAY[1,3])
AND d.date >= '2004-01-01' AND d.date <= '2024-12-31';
```

Result: finished, 9422 rows, 25.4 s.

**3c. Same as 3a, reading the table by load id (what `run.py` does)**

```sql
SELECT DISTINCT d.permno FROM kaggle_crsp.daily d
WHERE d.load_id = 1 AND d.shrcd = ANY(ARRAY[10,11]) AND d.exchcd = ANY(ARRAY[1,3])
AND d.date >= '2004-01-01' AND d.date <= '2024-12-31'
AND d.permno IN (SELECT permno FROM market.stock_spans WHERE release_id = 1 AND permno IS NOT NULL);
```

Result: finished, 9422 rows, 0.7 s.

Original observation (2026-11-24, `pg_stat_activity`, a first probe that I then stopped): a query like 3a had been active for 12 minutes 15 seconds, and 12 minutes 19 seconds a little later, still not finished. The 12 minutes is a lower bound from that one observation, not a measured total. The reason it was slow was not determined; do not read it as a measured property of `daily_of()`.

## 5. Missing or zero values in the loaded CRSP rows (load 1, from 2004-01-01, every row, no exchange filter)

```sql
SELECT count(*) AS n_rows,
  count(*) FILTER (WHERE prc IS NULL) AS prc_null,
  count(*) FILTER (WHERE prc = 0) AS prc_zero,
  count(*) FILTER (WHERE ret IS NULL) AS ret_null,
  count(*) FILTER (WHERE shrout IS NULL) AS shrout_null,
  count(*) FILTER (WHERE shrout <= 0) AS shrout_nonpositive
FROM kaggle_crsp.daily
WHERE load_id = 1 AND date >= '2004-01-01';
```

Output (0.3 s):

```
n_rows | prc_null | prc_zero | ret_null | shrout_null | shrout_nonpositive
21392301 | 0 | 0 | 0 | 0 | 0
```

## 6. What the importer counted as nulled values for load 1

```sql
SELECT load_id, status, checks->>'nulled_values' AS nulled_values
FROM ref.loads WHERE load_id = 1;
```

Output (0.0 s):

```
load_id | status | nulled_values
1 | complete | 0
```

What the two outputs mean (read from the importer comment and code in `src/ggTrader/data/kaggle_import/crsp.py`):
the importer turns any number in the price columns that is not a finite number (NaN or infinity) into an empty value (NULL)
and adds the count of such values to `nulled_values`. A count of 0 therefore means the uploaded file contained no such
values in those columns. Query 5 adds that, from 2004-01-01 on, no row in the table has an empty price, a zero price, an
empty return or an empty or non-positive share count. The 21,392,301 rows in query 5 are all rows of every stock from
2004-01-01; the scan in the note read 20,379,285 of them (the rows of the 9,422 stocks it selected).
